# api_probe —— 批量测 API 在板子上通不通

**换接口 / 加新接口之前，先把 URL 丢进来跑一遍。** 不画屏，结果只打串口。

每个目标测两件事，各占一列：

1. **DNS** —— 域名解析成什么 IP（解析不出来、或结果可疑 = 被污染）
2. **HTTP** —— HTTPS GET 拿到什么状态码

## 怎么用

```bash
cd arduino/api_probe
cp secrets.h.example secrets.h     # 填 WiFi（不进版本库，见仓库根 README）
```

把要测的 URL 加进开头的 `PROBES` 表：

```cpp
static const Probe PROBES[] = {
    {"我的接口", "api.example.com", "https://api.example.com/v1/xxx"},
    //  ↑显示名      ↑测 DNS 用        ↑测 HTTPS 用（可以带完整参数）
};
```

```bash
cd ../.. && ./build.sh flash api_probe
./build.sh mon                     # 115200
```

烧进去就跑一轮，**每 30 秒自动重测**（可达性会变，重测能看出网络是不是在抖）。

```
--- 汇总 ---

  [可用] baidu(对照)

```

表里分三组：**已知被墙的加密货币站点**（反面教材，用来看工具怎么报「被墙」）、
**天气类**（核实老 Demo 还能不能用）、**国内对照**（`baidu`、腾讯财经）。

> **如果连国内对照都挂了，那是你板子的网络问题，不是墙** ——
> 先回去跑 [`../net_diag`](../net_diag) 看挂在哪一层。

## 怎么读结果

**`HTTP -1` 不是"接口返回了错误"，是"根本没连上"**（`HTTPC_ERROR_CONNECTION_REFUSED`）。
这个区别很重要：接口 404/500 说明网络是通的，只是用错了；`-1` 说明请求压根没出去。

**DNS 那列出现这些就是被污染**：

| 解析结果 | 含义 |
|---|---|
| `0.0.0.0` | 黑洞地址 |
| `169.254.x.x` | 链路本地地址，本来就不该出现在公网 DNS 结果里 |
| `104.244.x.x` / `199.59.x.x` / `157.240.x.x` | Twitter / Facebook 网段，拿这些 IP 顶包 |
| 同一域名不同 DNS 问出**完全不同**的答案 | 正常域名绝不会这样 |

> **判断依据：正常域名在不同解析器之间结果应该是一致的。**

## ⚠️ 可达性是快照，不是承诺

今天通的明天可能就被墙，所以加新接口之前要**在板子上实测**，而不是翻文档。
**也别用开发机的 `curl` 下结论** —— 开发机常挂代理，通不通跟板子无关。
（这块板子被这件事坑过一次，详细经过见 [`../../Notes.md`](../../Notes.md) §5.3。）
