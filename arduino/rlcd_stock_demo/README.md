# RLCD-4.2 A 股行情看板

连 WiFi → 腾讯财经取行情 + 60 日 K 线 → 画到 1bpp 反射屏。
**这是本项目里第一个真正能跑的联网 Demo。**

## 为什么用腾讯财经，而不是 CoinGecko

最初写的是 CoinGecko（加密货币行情），代码没问题，但**板子没有代理，直连被 DNS 污染**。
板子自测的证据（`../api_probe` 打的表）：

| 域名 | DNS 解析到 | 结果 |
|---|---|---|
| `api.coingecko.com` | `199.59.148.209`（Twitter 网段） | ✗ |
| `api.huobi.pro` | `157.240.8.36`（Facebook 网段） | ✗ |
| `api.coincap.io` | `0.0.0.0`（黑洞） | ✗ |
| `www.okx.com` | `169.254.0.2`（链路本地） | ✗ |
| **`qt.gtimg.cn`（腾讯财经）** | 正常 | **✓ 200** |
| `www.baidu.com`（对照） | 正常 | ✓ 200 |

解析出 `0.0.0.0`、`169.254.x.x`、或者 Twitter/Facebook 的 IP —— 这些都不是真实结果，
是投毒。**结论：板子没毛病，国外站点在这个网络下用不了。**

## 数据源与免责声明

行情来自**腾讯财经的公开接口**，两个都用 HTTPS：

| 用途 | 接口 |
|---|---|
| 实时行情 | `qt.gtimg.cn/q=sh000001,sz399001,...` |
| 60 日 K 线 | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` |

两个都是**非官方**的公开接口，选它是因为**国内可直连**（就是上面那张表测出来的）。

> ⚠️ 接口**随时可能变更或关闭**，本 Demo 不保证长期可用。真挂了先用
> [`../api_probe`](../api_probe) 确认是不是网络层面的事。
> ⚠️ 行情数据仅供学习，**不构成任何投资建议**。
> ⚠️ 默认刷新间隔 **60 秒**（`REFRESH_MS`）。**别改成高频轮询** ——
> 对免费接口不礼貌，也容易被封 IP。

### 跑起来应该看到什么

1. 屏幕先显示 `A股行情` + 进度提示，随即 `Connecting WiFi`
2. 连上后显示 IP，约 5 秒完成 NTP 对时（右上角开始显示「交易中 / 休市中」）
3. 数据到了之后出现大字行情 + K 线折线图
4. 之后**每 60 秒**拉一次新数据，屏上有倒计时

串口会同步打印状态行，字段含义见 [§5](#五市场状态与-ntp-对时)。

## 一、改标的

```cpp
#define SYMBOL_COUNT 3
static const char *SYMBOLS[SYMBOL_COUNT] = {"sh000001", "sz399001", "sz399006"};
static const char *TAGS[SYMBOL_COUNT]    = {"SH INDEX", "SZ INDEX", "CHINEXT"};
```

- **第一个是主标的**（大字 + K 线图），后面几个各占一行。想加行就改 `SYMBOL_COUNT`。
- 前缀：`sh` = 上交所，`sz` = 深交所。
- 指数：`sh000001` 上证指数、`sz399001` 深证成指、`sz399006` 创业板指
- 个股：`sh600519` 贵州茅台、`sz000001` 平安银行、`sh601318` 中国平安
- ETF 也行：`sh510300` 沪深300ETF
- **`TAGS` 可以直接写中文**（汉字点阵由根目录的 [`tools/gen_cn_font.py`](../../tools/gen_cn_font.py) 生成，用法见根 README「四、中文点阵字库」）。
  注意：接口其实也返回中文名，但那是 **GBK 编码**，直接拿来会乱码，所以这里自己写死。
- ⚠️ **改完中文文案要重跑字库生成脚本**，否则新字显示成空心框 —— 生成器怎么用见根 README「四、中文点阵字库」。

## 二、两个坑（都踩过，都真报错了）

### 坑 1：字段下标差一位，涨跌幅显示成了涨跌额

腾讯行情接口返回的**不是 JSON**，是 `~` 分隔的文本：

```
v_sh000001="1~上证指数~000001~3888.37~3936.52~...~~20260924161401~-48.15~-1.22~...";
                                                                  ↑         ↑
                                                            涨跌额   涨跌幅
```

**下标 29 是个空字段**（原始数据里有 `~~`），肉眼数下标极易差一位。
症状很有迷惑性：数字看着"像那么回事"，但涨跌幅其实是涨跌额。

正确下标（0 开始）：

| 下标 | 含义 |
|---|---|
| 1 | 名字（GBK，用不了） |
| 3 | 现价 |
| 4 | 昨收 |
| 30 | 时间 `yyyyMMddHHmmss` |
| 31 | 涨跌额 |
| 32 | 涨跌幅 % |

核对下标的命令（别靠眼睛数）：

```bash
curl -s 'https://qt.gtimg.cn/q=sh000001' | iconv -f GBK -t UTF-8 \
  | python3 -c "import sys; print(list(enumerate(sys.stdin.read().split(chr(34))[1].split('~'))))"
```

### 坑 2：K线字段名，个股和指数不一样

```cpp
JsonArray rows = d["day"];        // 指数用 day
if (rows.isNull()) rows = d["qfqday"];   // 个股用 qfqday
```

只写死一个的话，另一种标的会取到空数组，屏幕上一片空白。

## 三、这次新学到的东西

- **不是所有 API 都返回 JSON。** 腾讯行情接口是 `~` 分隔的文本，得手写 `pickField()` 拆字段。
  而同一个站的 K 线接口又是标准 JSON。**接口长什么样要看实际返回，别想当然。**
- **GBK 编码。** 中文名是 GBK，直接 `Serial.print` 会乱码。这里只取数字字段绕开了，
  真要显示中文得转码 + 自己做字库。
- **一次请求拿多个标的**：`q=sh000001,sz399001,sz399006` 逗号分隔，省两次请求。
- **折线图函数是通用的**：`drawSparkline()` 不认数据来源，换成温度、CPU 占用率、
  汇率都能直接抄。它跟 `drawText()` 一样是"跟业务无关"的那部分。

## 五、市场状态与 NTP 对时

屏幕右上角显示 **交易中 / 休市中 / 已收盘 / 未开盘 / 周末休市 / 未对时**。

板子原本不知道"现在几点"（没 RTC、也没对时），所以只能显示行情数据的时间戳。
结果 2026 年中秋休市那几天，那个时间连着好几天停在 `09-24 16:14` 不动，
看起来像时钟坏了 —— 其实数据完全正确。现在板子自己知道时间了，能直接告诉你"今天休市"。

### 核心设计：不维护节假日表

A 股休市安排每年由交易所公布，还要跟着调休走。写死在代码里，**一年就得改一次，必忘**。

改用**「数据反推」**：如果今天交易过，行情数据的日期必然是今天。

| 显示 | 判断依据 |
|---|---|
| 交易中 / 已收盘 / 午间休市 | 数据日期 **==** 今天，再看当前时刻落在哪个时段 |
| **休市中** | 数据日期 **!=** 今天、工作日、且已过 9:30（⇒ 节假日） |
| 周末休市 | 星期几就能判 |
| 未开盘 | 数据日期 != 今天，且还没到 9:30 |
| 未对时 | NTP 没同步上 —— 诚实降级，不装懂 |

**好处是一年到头不用动。** 代价是依赖接口日期的准确性：接口若返回陈旧数据，
会被误判成休市。

### NTP 对时

```cpp
configTime(8 * 3600, 0, "ntp.aliyun.com", "ntp.tencent.com", "cn.pool.ntp.org");
```

- **服务器必须选国内的**，跟行情接口一个道理（见文首那张可达性表）。`pool.ntp.org` 之类墙内同步不上。
- 实测 `ntp.aliyun.com` 在板子上可用，开机约 5 秒完成对时。
- 时区固定 +8（中国不用夏令时）。
- **开机没对上会每分钟重试** —— 网络不好不该让这功能永久失效。

串口每次拉数据会打一行，屏幕上显示的就是这几个值，省得靠猜：

```
[status] 现在 2026-09-25 15:00  数据 20260924161401  市场 休市中
```

## 六、已知限制

- **休市时价格不动是正常的。** 右下角的数据时间戳会停在最后一个交易日，
  但现在右上角会明确显示 `休市中`，不会再被当成时钟坏了。
- **板子重启后要重新对时**（几秒）。想保住时间得用板载的 **PCF85063 RTC**（I2C 接口），
  那是另一个话题。
- **状态判断依赖接口返回的日期。** 接口若返回陈旧数据，会被误判成休市。
- **交易时段硬编码**为 `9:15-11:30 / 13:00-15:00`（含集合竞价），
  **不处理临时休市、提前收盘**等特殊情况。
- **K 线是日线**，60 个交易日 ≈ 3 个月。想要分时/周线改 URL 里的 `day` 参数。
- **`setInsecure()` 跳过 HTTPS 证书校验**。Demo 够用，**正式项目要把站点根证书装进
  板子的信任库**，别再跳过。
