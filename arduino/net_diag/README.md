# net_diag —— 网络分层诊断

板子连不上外网时用它定位**问题出在哪一层**。**不画屏，结果只打串口。**

## 怎么用

```bash
cd arduino/net_diag
cp secrets.h.example secrets.h     # 填 WiFi（不进版本库，见仓库根 README）
cd ../.. && ./build.sh flash net_diag
./build.sh mon                     # 115200
```

烧进去就一直跑，**每 15 秒重来一轮**，所以可以边改路由器设置边看结果。

## 测哪六层

自下而上，**哪层挂了就报哪层**，第 0 层过不去后面的就不测了：

| 层 | 测什么 | 挂了说明 |
|---|---|---|
| 0 | WiFi 关联 | 名字/密码/频段的问题（5G 专属 SSID 连不上） |
| 1 | DNS 解析 | 路由器给的 DNS 有问题，或被污染 |
| 2 | TCP 直连 443 | DNS 通了但网络到不了 —— 路由器/运营商层面拦了 |
| 3 | 明文 HTTP | 最基本的出网能力都没有（网页认证？） |
| 4 | HTTPS 国内站点 | TLS 握手本身能不能成（对照组） |
| 5 | HTTPS 目标站点 | **前面都过、只有这步挂 = 目标被墙** |

## 改目标

默认目标是 `api.coingecko.com`（一个**已知被墙**的站点，正好用来看工具怎么报「被墙」）。
换项目时改开头这两行：

```cpp
const char *TARGET_HOST = "api.coingecko.com";
const char *TARGET_URL  = "https://api.coingecko.com/api/v3/ping";
```

## 怎么读结论

```
第 4 层过、第 5 层挂  ->  目标站点被墙，换个 API 或者自己搭个中转
第 3 层就挂           ->  根本没出网
第 1 层挂             ->  换 DNS 试试（223.5.5.5 阿里 / 1.1.1.1 Cloudflare）
第 0 层挂             ->  WiFi 名字/密码/频段的问题
```

DNS 那一层还会自动认几个**投毒特征**：解析出 `0.0.0.0`（黑洞）或 `127.0.0.1`
就直接报「被污染」。

## ⚠️ 别用电脑的 `curl` 判断板子的联网能力

开发机常挂代理，`curl` 通是**代理**的功劳，跟板子的处境无关。
**要试某个接口能不能用，就在板子上跑 [`../api_probe`](../api_probe)**；
为什么会这样、实测数据长什么样，见 [`../../Notes.md`](../../Notes.md) §5.3。
