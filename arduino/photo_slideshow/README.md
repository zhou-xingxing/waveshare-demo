# photo_slideshow —— 照片幻灯片

把手机/电脑里的照片转成屏幕能显示的黑白图，轮流显示在反射屏上。
**不用联网**，图片存在板子自己的 flash 里。

```
照片  ->  tools/img2slides.py  ->  arduino/photo_slideshow/data/*.bin  ->  板子的 LittleFS  ->  屏幕
```

## 〇、开始之前

环境、依赖库、板子配置见[根 README](../../README.md) 的「二」「三」两节，这里不重复。
需要装的东西只有 U8g2 和 Pillow（`pip3 install pillow`）。

> ⚠️ **这块屏只有黑白两色，没有灰度。** 照片必须先转成 1bpp 才能显示。
> 转换不是简单二值化，要做**抖动**（用黑白点的疏密模拟灰阶）。
> 为什么这么做、字节序怎么定的，见 [`tools/img2slides.py`](../../tools/img2slides.py)
> 开头的说明和 [`Notes.md`](../../Notes.md) §6.5。

## 一、端到端流程

```bash
# 1. 转图 —— -o 是必须的，指向本目录的 data/
python3 tools/img2slides.py ~/Pictures/我的照片 -o arduino/photo_slideshow/data

# 2. 烧固件（首次必须）
./build.sh flash photo_slideshow

# 3. 传图片
./build.sh slides photo_slideshow

# 4. 看效果
./build.sh mon
```

> ⚠️ **第 2、3 步的顺序不能反。** 分区表是跟着固件一起烧进去的（写 flash 的 `0x8000`）。
> 板子上如果还是旧分区表，图片传进去了也没人认，屏幕会显示「文件系统没挂上」。
> 真遇到了就补烧一次固件，不用擦整片 flash。

**日常换图只需要重跑第 1 步和第 3 步**，不用重新编译。

### 图片放哪、怎么排序

- 默认输出到本目录的 `data/`，每张固定 **15000 字节**
- 文件按名排序编号：`slide_000.bin`、`slide_001.bin`… **这就是播放顺序**
- 每次跑转换脚本会**先清掉上次的 `slide_*.bin`**，所以删掉的照片不会留在板子上继续播
- 想调整顺序就改源文件名（脚本按文件名排序输入）

### 存哪、能放多少

`partitions.csv` 覆盖了分区表，给图片划出 **9.875 MB**（约 690 张）。

这个覆盖是**只在本题程生效**的 —— 别的 Demo 照旧，`build.sh` 里那串 FQBN 一个字没改。
原理见 [`Notes.md`](../../Notes.md) §6.6。

## 二、屏幕上是什么

开机后按顺序轮播，每张停 5 秒。串口（115200）可以控制：

| 按键 | 作用 |
|---|---|
| `n` | 立刻看下一张（调图的时候不用干等 5 秒） |
| `+` / `-` | 停留时间调长 / 调短（1~60 秒） |

串口还会打印每张的**分段耗时**（清屏 / 画图 / 送屏）和文件名。

屏幕上出现文字说明是这两种情况（正常轮播时屏幕上不会有字）：

- **「文件系统没挂上」** → 板子上还是旧分区表，见上面第一节的警告，先烧固件
- **「没有找到图片」** → 还没跑转换脚本，或者还没跑 `build.sh slides`

## 三、参数怎么调

**参数全表和调参心法在[根 README 的「五、图片转黑白点阵」](../../README.md)**，这里不重复
（那两个脚本是通用的，不属于本题程）。

对本题程特别要紧的两条：

1. **主体太小，建议裁（`--crop`）。** 屏幕只有 400×300，脸占 46 像素还是 94 像素，
   是「一团白斑」和「看得出五官」的区别 —— 比调任何参数都管用。
   （但**裁哪块是用户的决定**，别替他挑窗口，理由见[调参心法](../../README.md)）
2. **调参数时先别烧。** 用 [`tools/show_slide.py`](../../tools/show_slide.py) 直接读 `.bin`
   在终端看，或 `--png` 存图看完整的 1:1。烧一次 25 秒，来回试很慢。

## 四、已知限制

- **最多认 200 张**（`.ino` 里的 `MAX_SLIDES`）。分区能放约 690 张，但名字表是静态分配的，
  超了串口会提示。要更多就改大 `MAX_SLIDES`，每多一张多占 32 字节 RAM。
- **不压缩**。每张固定 15000 字节。幻灯片几秒才换一帧，压缩省下的空间换不来什么，
  而且抖动后的照片是高频噪声，RLE 之类的压缩率本来就很差。
- **换图时会看到一条扫过去的带子**。ST7305 没有双缓冲，整屏是分 50 次写进去的。
  这和官方计数器 Demo 的表现一样，不是本题程的问题。
- **换一张图要 55 ms**（实测）：`drawXBM` 画图 45~48 ms + `sendBuffer` 送屏 10 ms。
  幻灯片 5 秒才换一张，无所谓；但**想改成动画的话这就是天花板**（≈18 fps），
  而且瓶颈是 CPU 不是 SPI —— 原因和优化思路见 [`Notes.md`](../../Notes.md) §6.5 末尾。
- **1bpp + 抖动是有损的**：照片里的人脸、天空这类大面积渐变会有可见的网点纹理（这是原理决定的，
  不是 bug）。**线条画、截图、文字类的图转出来效果最好**。
- 想改分辨率要同时改两处：`tools/img2slides.py` 的 `WIDTH/HEIGHT` 和 `.ino` 里的
  `LCD_WIDTH/LCD_HEIGHT`。不一致的话板上会按文件大小校验挡下来并报错（不会花屏）。
