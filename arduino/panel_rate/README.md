# panel_rate —— 量出面板真实的刷新率

**一个诊断工具**，回答一个问题：这块屏每秒到底刷新几次？

**实测答案：面板 27 Hz。** 详见下面「实测结果」。

```bash
./build.sh flash panel_rate
./build.sh mon
```

## 为什么需要它

关于这块屏的刷新率，手上有两个容易搞混的数：

| 数字 | 出处 | 实际是什么 |
|---|---|---|
| 约 **80 fps** | 官方计数器 Demo 的串口输出 | **MCU 每秒能推几帧**（纯 SPI 吞吐），跟面板显示多少帧无关 |
| **0.25~32 Hz** | 第三方资料（`Notes.md` §1.1） | 面板刷新率。**实测 27 Hz 落在区间内，这条原本就是对的** |

两个数说的**都不是**「面板每秒真正刷新几次画面」。本程序把这两件事分开量：

- **push fps** —— MCU 每秒画完+推完几整帧（复刻官方 Demo 的算法）
- **TE Hz** —— **面板每秒真正刷新几次** ← 这个才是刷新率

## TE 是什么，为什么量它就能得到答案

**TE（Tearing Effect）是面板自己的帧同步输出引脚**，本板接在 **GPIO6**。
面板每刷完一帧就吐一个脉冲，**一个脉冲 = 一帧**。数一秒有多少个脉冲，
就是面板的真实刷新率 —— 不用查数据手册、不用猜。

驱动初始化时就发了 `0x35`（Tearing Effect Line ON，参数 `0x00` = 只输出垂直消隐，
所以每帧恰好一个脉冲），只是从来没人读这个脚。

> 数据手册里 TE 的极性和上下拉没写清楚，硬编码一种可能什么都测不到。
> 所以程序会把**四种组合**（上升/下降沿 × 有无内部上拉）各试 300ms，
> 哪组数得到脉冲就用哪组，并把结果打在串口上。

## 实测结果（2026-09-25，微雪 ESP32-S3-RLCD-4.2）

```
=== panel_rate：量面板真实刷新率 ===
[te] 探测 TE 引脚（每种组合 300ms）...
[te]   上升沿 / 无上下拉     8 个脉冲   ← 有信号
[te]   下降沿 / 无上下拉     8 个脉冲   ← 有信号
[te]   上升沿 / 内部上拉     8 个脉冲   ← 有信号
[te]   下降沿 / 内部上拉     8 个脉冲   ← 有信号
[te] 用「上升沿 / 无上下拉」
[rate] TE =   27.0 Hz    push =   69.0 fps    （每显示 1 帧，MCU 推了 2.6 帧）
```

**面板 27 Hz，MCU 能推 69 fps。** 结论：

- **面板是瓶颈** —— MCU 每推 2.6 帧，面板才显示 1 帧，多推的直接丢掉。
  **画得再快也不会更流畅**，要提帧率只能减少推帧量（局部刷新、压缩），或者干脆按 27 fps 推。
- 27 Hz ≈ 电影（24 fps），**够做动画**，但谈不上丝滑。
- 现在 MCU 是以 69 fps 盲写 27 Hz 的屏，**会撕裂**。要上动画得用 TE 同步写入
  （在垂直消隐期写显存）—— TE 这个脚存在的意义就是这个。

> 四种极性组合都数到 8 个脉冲（300ms × 27 Hz ≈ 8）—— 这恰好说明测对了：
> 脉冲串每周期有一个上升沿和一个下降沿，数哪个都是同一个数。
> 上拉与否结果一样，说明面板是推挽驱动。

屏幕上除了两个数字，还有一条来回扫的竖条 —— **人眼判断「动起来顺不顺」比看数字直观**，
两者可以互相印证。

## 怎么读结果

- **TE Hz 远小于 push fps** → 面板是瓶颈，MCU 再快也没用。屏幕上的更新率由 TE 决定。
- **TE Hz ≈ push fps** → 两边刚好匹配。
- **push fps 远小于 TE Hz** → MCU/SPI 是瓶颈，得优化推帧（局部刷新、压缩、提高 SPI 时钟）。

## 已知限制

- **只测量，不改变面板配置。** 想试低功耗模式（`0x39`）看 TE 怎么变，
  需要在驱动里加一个发原始命令的入口 —— 上游驱动把 `U8X8_MSG_BYTE_SEND` 丢掉了
  （`ST7305_U8g2.cpp:102`），`u8g2_SendF()` 走不通，而本题程**不修改上游驱动文件**。
- `0x38` = High Power Mode、`0x39` = Low Power Mode 这两个含义来自
  [kylehase/ESPHome-ST7305-RLCD](https://github.com/kylehase/ESPHome-ST7305-RLCD)
  的源码注释（该驱动的初始化序列和微雪的逐寄存器一致），**不是官方数据手册**。
- 面板处于睡眠模式时 TE 输出行为不同，可能量到 0。
